# 青砚作品集性能优化第一阶段设计

## 目标与边界

本阶段以 `qingyan-studio` 的提交 `28f5b91` 为唯一基线，在独立副本的 `perf/phase-1` 分支中完成诊断和最小实验。不得修改原仓库、正式 `main`、正式 GitHub Pages、正式域名或 DNS；不得购买套餐或把测试结果直接升级为迁移结论。

## 已确认的性能基线

- 首页 HTML 为 24.4 KB，本次网络下 TTFB 为 1.69–2.14 秒。
- 首屏海报 `hero-lake.jpg` 为 424 KB、基线 JPEG，下载完成约 3.09–3.81 秒，慢网下会从上到下逐步显现。
- 首屏自动播放 `hero-day.mp4` 为 14.08 MB；读取前 1 MB 约 3.47–4.91 秒。
- 桌面端互动视频 `hero-sunset.mp4` 为 8.68 MB，当前延迟到互动后加载。
- 两段首屏 MP4 均为 Fast Start；视频索引位置不是当前主要问题。
- GitHub Pages 对 HTML、海报和视频返回 `Cache-Control: max-age=600`，仅缓存十分钟。
- DNS 耗时不是主要瓶颈；当前链路的 TLS、TTFB 和吞吐更显著。
- 浏览器精确 LCP、图片解码耗时和视频首帧时间暂未可靠测得，保持“未测”。

## 实验结构

### 实验 A：稳定占位与完整解码后淡入

保持现有构图、文字和交互不变。首屏先显示稳定的低成本占位层，真实海报在 `decode()` 成功或 `load` 回退后一次性淡入。加载失败时继续保留占位层，不显示破图或空白。

独立提交，只改首页、首屏相关样式和首屏加载脚本。回滚方式为撤销该提交。

### 实验 B：响应式首屏图片与优先级

从同一原图生成手机、平板和桌面档位，优先测试 WebP，并保留 JPEG 回退。HTML 使用 `picture/srcset/sizes`，首屏维持 `fetchpriority="high"` 与 eager 加载；非首屏媒体继续 lazy loading。

独立提交，保留原始海报文件，不覆盖源文件。回滚方式为撤销该提交并删除新增派生文件。

### 实验 C：单段视频转码

仅对 `hero-day.mp4` 生成一个测试版，不替换其他视频。目标是保持 1080p 视觉可接受、Fast Start 和浏览器兼容，同时显著降低体积与首帧等待。原视频保持不变。

独立提交。页面仅在实验分支引用测试视频；回滚方式为撤销该提交并删除测试视频。

## 托管对照

1. GitHub Pages：作为当前基线，不重新发布正式站。
2. 阿里云 ESA Pages：优先建立独立测试项目。免费公共链接仅供测试、需要 Token 且有效期 60 分钟；不绑定正式域名。创建需要用户现有阿里云账号、实名认证状态及 GitHub 授权。
3. Cloudflare Pages：作为海外网络对照。使用独立项目和平台测试域名，不绑定正式域名。免费版单文件上限为 25 MiB，因此只部署优化后的测试素材。

若账户、授权或凭据不可用，则停止在创建动作之前，记录阻塞和最短手动步骤，不使用临时陌生账户，也不请求或记录长期密钥。

## 测量方法

- 在同一设备、浏览器和当前网络环境中测试。
- 每个版本至少记录三次冷缓存和三次热缓存。
- 网络层分别记录 DNS、TCP、TLS、TTFB、下载时间、文件大小、重定向次数和缓存响应头。
- 浏览器层记录可可靠获得的首屏显示、图片完整显现、视频首帧和布局稳定性；无法可靠取得的指标标记为未测。
- GitHub、ESA 和 Cloudflare 使用相同构建内容与同一组关键资源，避免将代码差异误判为托管差异。

## 验收标准

- 首屏不再出现明显的从上到下分块显现。
- 图片完成后整体淡入，加载失败时占位稳定。
- 手机、平板和桌面构图不变形、不遮挡文案、无横向溢出。
- 测试视频体积显著下降，且首帧等待较基线稳定缩短。
- 只有当多次测试显示明显改善、免费或低成本条件成立、且中国大陆访问稳定时，才提出正式迁移建议。

## 明确不做

- 不修改正式仓库和生产分支。
- 不推送到正式 GitHub Pages。
- 不修改或绑定正式域名和 DNS。
- 不购买套餐。
- 不批量转码或替换全部视频。
- 不以一次测速或海外节点结果代表中国大陆普遍体验。
